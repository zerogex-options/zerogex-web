# ZeroGEX Web — API Call Inventory

*Every network call the web app makes, grouped by direction and categorized by
system. Generated by walking every `fetch(`, SDK call site, WebSocket, and route
handler in `frontend/`.*

---

## 0. The three-hop architecture

Every browser data request funnels through one place. Understanding the hops is
what makes the rest of this document readable:

```
┌──────────┐   same-origin /api/*   ┌─────────────────┐   Bearer key    ┌──────────────┐
│ Browser  │ ─────────────────────▶ │  Next.js BFF    │ ──────────────▶ │  FastAPI     │
│ (React)  │                        │ (58 handlers)   │  127.0.0.1:8000 │  backend     │
└──────────┘                        └─────────────────┘                 └──────────────┘
     │                                       │
     │  wss://api.zerogex.io/ws?ticket=…     │  Stripe · Google · Apple · Resend
     └──────────────────────────────────────▶│  PostHog · X Ads · RSS feeds
                                             ▼
```

**Three transports reach the FastAPI backend:**

| Transport | Code | Used by | Auth |
| --- | --- | --- | --- |
| BFF proxy | `core/api/proxy.ts` → `proxyToApi` | Browser `/api/*` calls | `Authorization: Bearer $ZEROGEX_API_TOKEN` + `X-End-User-Token` (minted per user) |
| Server fetch | `core/api/serverFetch.ts` → `serverApiGet` | SSR / ISR pages, OG images | Bearer key only (no per-user attribution; responses are cached & shared) |
| Direct helpers | `core/apiKeys.ts`, `core/xPost.ts`, `app/api/news/route.ts` | Admin + news routes | Bearer key, bypasses `proxyToApi` |

**Tier gate.** `core/api/apiTierGate.ts` is an ordered, first-match-wins *denylist*
applied inside the BFF proxy. Unmapped paths pass through (fail-open):

| Prefix | Required tier |
| --- | --- |
| `/api/backtest/runs/shared` | `public` (carve-out) |
| `/api/tradeworkz/admin` | `admin` |
| `/api/signals/advanced`, `/api/signals/trade-bias`, `/api/signals/trade-bias-history` | `pro` |
| `/api/signals` | `basic` |
| `/api/backtest` | `pro` |
| `/api/gex`, `/api/flow`, `/api/forced-flow`, `/api/replay`, `/api/option`, `/api/max-pain`, `/api/technicals` | `basic` |
| `/api/market/volatility` | `basic` |

Kill-switch: `BILLING_API_TIER_GATE_ENABLED=0`.

## 4. WebSocket — 1 connection

| Step | Detail |
| --- | --- |
| 1. Ticket | Browser `POST /api/ws/ticket` (`core/quoteStream.ts`) |
| 2. Mint | `core/api/wsTicket.ts` signs HS256 JWT — `sub` = user id, `aud` = `ws`, 60s TTL, secret `ZEROGEX_END_USER_TOKEN_SECRET` |
| 3. Connect | `new WebSocket(NEXT_PUBLIC_WS_URL + '?ticket=<jwt>')` → FastAPI `/ws` |
| 4. Frames | Symbol subscribe/unsubscribe; live quote ticks fan out through `applyLiveQuote()` |

Failure modes are all non-fatal: `401` (anonymous) and `503` (feature flag off or
secret unset) both fall back to HTTP polling. Gated by
`NEXT_PUBLIC_ENABLE_WEBSOCKET`.
